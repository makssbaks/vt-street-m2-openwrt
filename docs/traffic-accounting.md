# Учёт трафика VT Modem

В прошивку добавлены `vnstat2` 2.13, отдельная служба `vtmodem-traffic` и RPC
`vtmodem.traffic_status`. Чтение этой RPC не обращается к AT/QMI и не запускает
внешние команды: оно читает подготовленный JSON и текущие счётчики ядра.

## Что считается

- RX — принято модемом из сети оператора, TX — передано в сеть оператора.
- Учитывается фактический `l3_device` интерфейса `network.interface.modem`
  с протоколом `t99w175qmi`; разрешены имена `wwanN`.
- LAN и остальные интерфейсы автоматически не добавляются. Если модем сменит
  `wwan0` на `wwan1`, оба явно добавленных интерфейса входят в историю один раз.
- `today`, `month`, `total` — сохранённые значения vnStat. Их время записи
  находится в `updated_at`; период записи — 10 минут. Частое обновление веб-
  страницы не вызывает запись во flash. `collected_monotonic_ms` характеризует
  свежесть JSON, а не момент сохранения исторических байтов.
- `live` — свежие счётчики текущего экземпляра интерфейса, с `boot_id`,
  `ifindex` и монотонным временем. При смене экземпляра или уменьшении счётчика
  веб-интерфейс должен сбросить базу расчёта скорости. Эти значения нельзя
  прибавлять к `total`: часть трафика уже есть в базе.
- Все байтовые значения передаются десятичными строками без потери точности
  uint64. Отображение в ГБ использует 1 000 000 000 байт. Данные могут отличаться
  от биллинга оператора.

## Время, хранение и резервная копия

При первой загрузке календарный учёт ждёт подтверждённой синхронизации NTP
(события BusyBox ntpd со stratum 1–15). До этого доступен `live`, состояние
`waiting_for_time`, а день/месяц не показываются. Трафик до начала учёта не
включается в историю. Если NTP недоступен постоянно, исторический учёт не
начнётся до явного подтверждения времени пользователем; это явно сообщается
в API, а не заменяется датой сборки прошивки. `traffic_confirm_time(timestamp)`
проверяет совпадение времени браузера и роутера с допуском 120 секунд и только
после этого разрешает учёт. Команда не переводит системные часы. При расхождении
нужно сначала установить правильную дату в настройках системы. В статусе
`clock_source` различает `ntp`, `manual` и неподтверждённое время.
После перезагрузки ранее сохранённую историю можно читать ещё до NTP.

Собственная база — `/etc/vtmodem/traffic/vnstat.db`, собственный конфиг —
`/etc/vtmodem/vnstat.conf`. Штатная служба `vnstat` и пользовательские
`/etc/vnstat.conf`, `/etc/config/vnstat` остаются без изменений. Два сервиса не
пишут в одну базу. Приватный конфиг задаёт календарный месяц с первого числа
и местное время роутера; изменение системного часового пояса не пересчитывает
ранее накопленные периоды vnStat.

vnstatd сбрасывает данные по SIGTERM перед штатной остановкой. При внезапной
потере питания возможна потеря последнего несохранённого интервала. Смена
состояния интерфейса также вызывает сохранение.

Для `sysupgrade -b` и сохранения настроек при обновлении hook сначала запрашивает
у собственного supervisor ограниченную по времени остановку процесса vnstatd
с сохранением данных. Изменённый код vnstatd возвращает ошибку при неудачной
финальной записи SQLite; наличие этого исправления проверяется отдельной
командой capability до запуска. После успешного завершения vnstatd команда
`vt-traffic-db backup` через SQLite Online Backup API создаёт согласованный снимок
`/etc/vtmodem/traffic-backup.db` и timestamp `traffic-backup.time`. Ошибка
снимка останавливает резервное копирование, чтобы старый файл не считался
новой копией. Учёт автоматически возобновляется также после ошибки снимка.
Сеть, интерфейсы и модем при этом не перезапускаются. Добавление интерфейсов
коллектором исключается файловой блокировкой на время снимка. Живая база не
добавляется в обычный список конфигурационных
файлов. На новой системе снимок восстанавливается, только если живой базы
ещё нет. Восстановление поверх работающей базы не выполняется.

Подтверждение финальной записи относится к уже собранным данным vnStat.
Последний опрос счётчиков может отставать на настроенные 10 секунд; остановка
не обещает нового измерения ядра точно в момент запроса резервной копии.

## Проверки

```sh
TZ=UTC ucode scripts/tests/test-vtmodem-traffic.uc
python3 scripts/tests/test-vt-traffic-db.py
python3 scripts/tests/test-vt-traffic-service.py
```

Для C-теста требуются SQLite headers и библиотека для хостовой системы.
Проверяются большие счётчики, выбор текущего периода, отсутствие удвоения
LAN, смена ifindex, чтение во время SQLite-транзакций, блокировка/повреждение
базы, срок завершения и сохранение предыдущего снимка при ошибке, NTP-ворота
и остановка sysupgrade backup при ошибке снимка. Это хостовые проверки;
реальная запись статистики после перезагрузки роутера проверяется отдельно.
