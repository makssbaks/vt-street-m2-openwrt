# VT Modem release 19: исправления и новые возможности

Дата: 13 сентября 2026. Основа — `audit/firmware-20260913`, commit
`40111adec677edf331d2109b9a533b747a7912da`.
Этот документ описывает изменения исходников после
[аудита](firmware-audit-20260913.md), а не результат установки на роутер.

## Исправления аудита

| Аудит | Изменение | Проверка на хосте |
| --- | --- | --- |
| A01, A12 | UP публикуется после проверки всех запрошенных IP-семейств; проверяется согласование Raw IP | QMI lifecycle, sysfs |
| A02, A13 | Владение CID/PDH сохраняется до UP; очистка учитывает поколение USB; WDS-монитор передаёт потерю сессии netifd | Lifecycle, USB hotplug, startup handoff |
| A03, A04 | Полный конечный ответ AT, общий монотонный срок блокировки/записи/чтения; статус читается из кэша отдельного сборщика | C socket/PTY, collector, RPC |
| A05 | Удаление сверяет исходный PDU под общей блокировкой; устаревшие кнопки списка отключаются | C и SMS UI |
| A06 | Отправка возвращает число подтверждённых частей и неоднозначный результат; повтор неизвестной операции не выполняется | C, SMS jobs, SMS UI |
| A07 | PDU разбирается с новым состоянием и проверкой длины/UDH/Unicode | C, ASan/UBSan |
| A08 | Исправлены сегменты GSM-7/UCS-2 и сохранение нового черновика | SMS UI |
| A09 | Сохраняются пользовательский LAN MAC и ранее созданный fallback | Изолированная модель UCI |
| A10 | Проверяются CRC, длина, архитектура, сжатие, адреса и размер kernel; содержимое rootfs и NAND upgrade handler | Image/rootfs fixtures, package install |
| A11 | Исторические упаковщики больше не собирают смешанные ZIP из текущего дерева | Image/build fixtures |
| A14 | WAN назначается только при создании конфигурации; существующая firewall-зона сохраняется | USB hotplug |

Восстановление соединения не использует неудачный ping как повод для сброса.
Ручное «Остановить» сохраняет смысл. Если невозможно подтвердить освобождение
QMI-ресурсов, `CLEANUP_UNCERTAIN` останавливает автоматические повторы; для
продолжения нужны новое появление USB-устройства и явный запуск интерфейса.
Это намеренное ограничение, исключающее повторное использование неизвестного CID.
IPv6-адрес модема не выдаётся за делегированный префикс LAN.

## Счётчик трафика

На странице статуса добавлены принято/передано/всего за сегодня, календарный
месяц и с начала учёта; отдельно — текущие счётчики интерфейса и скорость.
1 ГБ = 1 000 000 000 байт. Учитывается интерфейс модема, LAN не суммируется.
Большие счётчики передаются строками, а разности вычисляются до преобразования
в число JavaScript. Пересоздание интерфейса, уменьшение счётчика и смена загрузки
сбрасывают базу расчёта скорости.

История хранится отдельным экземпляром vnStat на постоянном разделе, обычно
с записью каждые 10 минут. Веб-опрос не вызывает запись flash. При внезапном
отключении питания последние несохранённые данные могут потеряться.
Время последней записи показано отдельно от текущей скорости. Живые счётчики
не прибавляются к истории повторно.

Календарный учёт начинается после NTP или явного подтверждения правильного
времени пользователем. Подтверждение сравнивает часы браузера и роутера,
не переводит системные часы. До начала учёта доступны текущие счётчики;
предыдущий трафик не включается в историю задним числом.

Резервная копия запрашивает финальную запись собственного vnstatd и создаёт
согласованный SQLite-снимок. Ошибка останавливает создание новой копии.
Модем и сетевые интерфейсы этим механизмом не перезапускаются.
Подтверждается запись уже собранных данных; их последний опрос может отставать
на настроенный интервал 10 секунд.
Подробности и ограничения: [учёт трафика](traffic-accounting.md).

## Настройка антенны

Добавлены графики RSRP, RSRQ и SNR за последние десять минут и сравнение
до шести сохранённых замеров. Сравниваются свежие показатели одной основной
соты; смена соты и пропуски разрывают линию графика. Повторные или устаревшие
ответы не добавляют новые точки. Замер использует медиану последних точек
одной соты, а не одиночный скачок.

Режим включает обновление каждые пять секунд и восстанавливает прежний интервал
после выключения. Замеры сохраняются в текущем браузере; история графика —
только на открытой странице. Изменение направления антенны выполняет пользователь.
Режим не изменяет диапазоны, фиксацию соты или мощность модема и не обещает
физическое усиление сигнала.

## Сборка и проверки

`vtmodem` имеет `PKG_RELEASE=19`. Все пять feeds закреплены по commit.
В образ записывается идентификатор проекта, OpenWrt, feeds и патчей; версия
выводится в статусе. Старые патчи C включены непосредственно в поддерживаемые
исходники. Пакет устанавливает новые службы, ACL, RPC, UI и SQLite helper вместе.
Отдельный проверяемый патч vnStat нужен для подтверждения финальной записи.

Единая команда проверки — `bash scripts/test-vtmodem-web.sh`.
Нужны Node.js, Python, C compiler, make, SQLite headers/library и host ucode
с модулем fs из закреплённого OpenWrt. Набор проверяет JS-формы и реальную
логику представления с моделью DOM, ucode RPC/парсеры/задачи, shell lifecycle,
C транспорт, базу и фактические prepare/compile/install правила пакета.
В локальной среде shell-сценарии выполнены через `/bin/sh`; поведение целевого
BusyBox и procd остаётся частью проверки готового образа на устройстве.

Отдельный workflow `VT Modem fast checks` запускает JS/C/shell/packaging проверки
на pull request без компиляции прошивки. Полный workflow дополнительно выполняет
ucode-тесты именно на интерпретаторе из закреплённых исходников OpenWrt.

Полная MIPS-сборка, физическое исчезновение USB, восстановление после загрузки,
реальные SMS и запись истории на NAND ещё не проверены для release 19.
Хостовые модели эти испытания не заменяют. Готового sysupgrade-образа этот
документ сам по себе не подтверждает.

## Следующий этап

1. Запустить workflow `Build VT-STREET-M2 OpenWrt 25.12` для ветки исправлений.
2. Проверить `VALIDATION.txt`, build identity, состав rootfs и SHA256 полученного
   образа. Новый комплект требует согласованных C/RPC/UI и vnStat; частичная
   установка одного `status.js` для него не подходит.
3. Сохранить конфигурацию действующего роутера. До прошивки предъявить конкретный
   проверенный образ и предупредить о перерыве связи.
4. После загрузки проверить службы, интернет, интерфейс, время и прирост RX/TX;
   затем сохранение истории после планового перезапуска. Проверки, меняющие
   USB/радио или передающие SMS, выполнять отдельными явно выбранными действиями.

Отдельно остаются журнал связи с обезличенной выгрузкой диагностики, графики
трафика по дням, произвольная дата расчётного месяца и ручной сброс статистики.
Полная 5G-телеметрия, SIM PIN, аппаратная проверка L860 и bootloader recovery
не входят в подтверждённые возможности этого изменения. Значение RX3/RX4
`-140 dBm` само по себе не доказывает неисправность: семантика признака
`rx_diversity` именно этой версии модема ещё требует документации/проверки.
